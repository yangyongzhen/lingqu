**关键路径**：P1 → P2 → P4 → P5 → P7。P3 可与 P2 并行；P6 依赖 P5；P8 依赖 P7。

```
P1 ──┐
     ├─→ P2 ──→ P4 ──→ P5 ──→ P6 ──→ P7 ──→ P8
P3 ──┘            ↑
      （P3 的规则库在 P4 被消费）
```

**排序理由**（不是随便排的）：

1. **P1 先做**：AI 面板不通，后面 P2–P6 的产出只能"看数字"，不能让 cjh 解释与改码；且 P1 风险最低（插件现成）。
2. **P2 早于 P4**：先有清单与评分，才知道"要改什么、该不该改"；没有画像的改造是盲改。
3. **P3 与 P2 并行**：依赖扫描与清单扫描共用 `cargo metadata` 采集层。
4. **P5 必须早于 P7**：5 个样本要跑，先得有一条能出一键 HAP 的流水线。
5. **P8 放最后但要留 1.5 周**：迁移指南与演示是验收 A5 的硬指标，不是收尾附赠。

## 每个阶段的统一结构

所有阶段都按同一张"任务卡"展开，字段固定：

- **目标**：一句话说清阶段结束时长什么样。
- **任务**：`T<阶段>-<序号>`，每条都是"一次坐进去能做完"的粒度，含**产出文件**。
- **出口判据**：可断言的验收条件（命令输出 / 文件存在 / 指标阈值 / 自检序列）。
- **证据**：判据对应的原始证据存哪（日志、JSON、截图、报告）。
- **依赖 / 风险**：前置阶段与已知坑。

> 阶段内**每条任务都要过门禁**（`./scripts/test.sh`）与文档三件套（CHANGELOG / 进度记录 / 需求追踪）。

## P1 · 对话通道接通（WS 流式 + 审批卡）

**目标**：右栏 AI 面板从"占位"变成"能真对话、能看到工具调用、能批危险操作"。

**为什么现在做**：后续所有阶段都要 cjh 参与诊断/改码；面板不通，AI 只存在于命令行。

| 任务 | 内容 | 产出 |
|---|---|---|
| T1-1 | 装配 `WsPlugin()`；capabilities 加 `ws:connect/send/close`、events `ws:frame/ws:state`、`scopes.ws: ["127.0.0.1"]` | `src/main.cj`、`assets/capabilities/default.json` |
| T1-2 | 页面连接状态机（idle→connecting→connected→closed）+ 引擎就绪自动连 + 断线重连 | `assets/ui/index.html` |
| T1-3 | 发送回合 + 帧分发：增量文本、`tool_start`/`tool_result`、`approval_request`、`error{code,retryable}` | 同上 |
| T1-4 | 审批卡：参数/diff 预览 + 「允许 / 只此一次 / 拒绝」，回 `approval_response` | 同上 |
| T1-5 | 会话最小集：新建 / 清空 / 切历史（`GET /api/sessions`） | 同上 |
| T1-6 | 自检增强：`ui_report` 加 `wsState / frames / toolCards / approvals`；自检序列自动发一句并断言 | `src/main.cj`、UI |

**出口判据**

1. 自检序列（`LINGQU_UI_PROBE=1`）产出：`wsState=connected`、`frames ≥ 5`、`toolCards ≥ 1`、`jsErrors=0`；
2. 手动触发一次危险操作，出现审批卡，点「拒绝」后 cjh 不执行、会话继续；
3. `cj-tauri check` 三方比对通过（ws 命令与事件都声明齐）。

**证据**：`.lingqu/ui-report.log` 序列 + 审批卡截图（人工目检一次）。

**风险**：`ws` 插件在 Windows 上按框架平台矩阵属"未验证"（Linux 已实机）。ai-chat 在 Windows 上跑通过，风险可控；
若真不通，退路是后端用 `stdx.net` 自建 WS（`cjh_host.cj` 已有 HTTP 客户端基础设施）。

### P1 完成记录（0.5.0，2026-10-30）

实测证据（`.lingqu/ui-report.log`）：

```
常规探针 LINGQU_UI_PROBE=1
  ws=connected  frames=2   lastFrameType=done  replyPreview="收到"
审批探针 LINGQU_UI_PROBE=approval（cjh 临时置严格）
  ws=connected  frames=13  tools=1 approvals=1 lastFrameType=approval_request   ← 卡片出现
  ws=connected  frames=268 tools=1 approvals=1 lastFrameType=done               ← 自动拒绝后回合继续
```

**审批验证配方**（cjh 默认宽松，不配 `capability` 段则所有工具放行——这是 cjh 的策略，工具不替用户改）：

```bash
# 1) 备份并临时开启严格审批
cp ~/.cjh/settings.json ~/.cjh/settings.json.bak
#    在 settings.json 里加："capability": { "enabled": true, "approval": ["*:*"] }
# 2) 起应用并跑审批探针（探针会在 12s 时自动点「拒绝」，验证回执链路）
LINGQU_UI_PROBE=approval ./scripts/run-dev.sh
# 3) 看结果
cat .lingqu/ui-report.log     # 期望 approvals=1 且之后仍有帧（回合继续）
# 4) 恢复配置
mv ~/.cjh/settings.json.bak ~/.cjh/settings.json
```

踩坑记录：cjh 配置里密钥在 `auth.json`（不在 `settings.json`），改写 `settings.json` 不会丢密钥。
