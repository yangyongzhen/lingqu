# 开发环境（Windows）

本文只写「跑起来必须满足什么」，每条都来自实测报错，不是抄文档。

## 二、环境变量

| 变量 | 什么时候要 | 值 |
|---|---|---|
| `CANGJIE_HOME` | 编译 / 运行 | `D:\Program Files (x86)\Cangjie` |
| `CANGJIE_STDX` | 编译 / 运行 | `<桌面版 stdx>\windows_x86_64_cjnative\dynamic\stdx` |
| `CANGJIE_STDX_OHOS` | 编 HAP | `<鸿蒙版 stdx>\linux_ohos_aarch64_cjnative\dynamic\stdx` |
| `CJ_TAURI_ROOT` | 跑 CLI 时不在框架仓内 | `E:\test\harmonyos\test\cj-tauri` |
| `DEVECO_HOME` | 打包 HAP | `D:\Program Files\Huawei\DevEco Studio` |
| `NATIVE_OHOS_SDK` | 交叉编译 | `<SDK>\HarmonyOS-NEXT-DB6\openharmony\native` |
| `LINGQU_CJH` | 覆盖内置 cjh 路径 | 任意 `cjh.exe` 绝对路径（不设则用仓内 `vendor/cjh/win-x64/`） |
| `LINGQU_CJH_PORT` | cjh web 端口 | 默认 `8765`，与 cjh / ai-chat 的既有约定一致 |
| `LINGQU_CJH_BUNDLE` | vendor 不可用时的安装包 | 一份 zip（Windows）/ tar.gz 的路径，由系统 bsdtar 解包到安装目录 |
| `WEBVIEW2_USER_DATA_FOLDER` | WebView2 数据目录不可写时 | 例如 `<工程根>\.wv2data` |

## 三、构建与运行

```bash
# 0) 换机器时先对齐本机绝对路径（框架路径 + 两处 -L<native>）
./scripts/setup.sh

# 1) 门禁（四道闸；-s 先派生骨架，-c 清增量缓存）
./scripts/test.sh -s
#    或 Windows 上：scripts\test.bat -s

# 2) 编译 + 起窗口（引擎由应用自己拉起）
./scripts/run-dev.sh -b
#    或 Windows 上：scripts\run-dev.bat -b
```

> 脚本一律 **bash 为准**（`scripts/*.sh`），Windows 的 `*.bat` 只负责找到 bash 再委托——
> 一份实现两个平台，与 cj-tauri / cjh 两个上游仓同口径。理由见 `docs/设计决策记录.md` 的 D-012。

## 四、踩过的坑（按报错原文索引）

| 现象 | 根因 | 处置 |
|---|---|---|
| `cjpm build` 报 `root package 'cli' imports package 'stdx.encoding.json' ... not added as a dependency` | 没设 `CANGJIE_STDX`（toml 里的 `${CANGJIE_STDX}` 展开为空） | 设 `CANGJIE_STDX` |
| 双击 / 启动即退出，退出码 `-1073741515`（0xC0000135） | 缺 DLL。用 `llvm-objdump -p main.exe` 看导入表，常见缺 `libcjtbridge.dll` | PATH 加 `框架\native`；或拷 DLL 到 exe 旁 |
| 缺 `WebView2Loader.dll`（导入表已齐时） | 它不在导入表里，是按名加载 | PATH 加框架 `native\webview2`（`run_win.bat` 同口径），或拷到 exe 旁 |
| `资产未找到：ui/index.html` | launcher 用相对路径；**工作目录必须是工程根** | `cd` 到 `lingqu\` 再运行 |
| `[cj-tauri] 已从 assets/capabilities 加载 0 个 capability 清单` | 同上，工作目录不对 | 同上 |
| `create WebView2 controller failed: 0x800700AA` | WebView2 用户数据目录不可用（被占用 / 不可写） | 设 `WEBVIEW2_USER_DATA_FOLDER` 到可写目录 |
| `create WebView2 controller failed: 0x8000ffff` + Chromium `Check failed: false` | 宿主环境不允许 Chromium 起子进程 / 开命名管道（容器、受限沙箱里常见） | 换到普通桌面会话运行；这不是应用问题 |
| 跑 `.ps1` 报「数组索引表达式丢失或无效 / 字符串缺少终止符」，且报错行里的中文是乱码 | 历史坑：本仓已弃用 `.ps1`（ADR D-012）；确需写就必须存 UTF-8 **带 BOM** | 用 `scripts/*.sh` + `*.bat` |
| Windows 上 `scripts/*.sh` 里命令全 `exit 127` | `CANGJIE_HOME=D:\...` 这种 Windows 形式路径在 MSYS 的 PATH 里无效 | 脚本内已统一 `to_posix` 归一化 |
| `cj-tauri check` 提示"骨架漂移" | 改了 `cj-tauri.toml` 或 `assets/` 但没重跑 sync | `cj-tauri sync desktop` / `sync ohos` |
| 前端拿到 `command not allowed` | 命令注册了但没在 `assets/capabilities/default.json` 放行 | 两边必须成对；`cj-tauri check` 的三方比对该报这一条 |
| `ld.lld: error: failed to write the output file: Permission denied` | 上一版 `main.exe` 还在跑，产物文件被占用 | 先关窗口 / `Stop-Process -Name main -Force` 再 `cjpm build` |
| 链接报 `undefined symbol: _CGP7cjTauri…`（符号名是一串乱码） | 业务包公开接口变了，但骨架的增量缓存还是旧对象 | `./scripts/test.sh -c`（删 `targets/desktop/target` 与 `target/` 后重建） |

## 五、不要手改的东西

`targets/` 整个目录是 `cj-tauri sync` 派生的（`.gitignore` 已忽略），内含本机绝对路径。
手改会被 `cj-tauri check` 判为漂移并在下次 sync 时覆盖——**要改就改 `cj-tauri.toml`、`src/`、`assets/`**。

## 六、鸿蒙端（PC / 2in1）

```bash
export CANGJIE_STDX_OHOS=D:/cangjie-stdx-ohos/linux_ohos_aarch64_cjnative/dynamic/stdx
cd targets/ohos
bash build-hap.sh              # 编 HAP
bash build-hap.sh --install    # 编完装到设备并拉起
```

模板不带签名证书：首次要在 DevEco 里 *File → Project Structure → Signing Configs* →
勾「Automatically generate signature」（需登录华为账号）。不签名只能出 `*-unsigned.hap`，装不进设备。

鸿蒙端能力位现状（见框架 `docs/平台能力矩阵.md`）：窗口 / 页面 / IPC / 多窗口 / 菜单 / 剪贴板可用；
托盘 / 全局快捷键 / 拖放 / 原生对话框 / 系统通知**能力位为 0**，工具在鸿蒙端要走应用内替代实现。
