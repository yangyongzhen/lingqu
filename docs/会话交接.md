## 三、架构：三层，别混

```
cj-tauri.toml                 应用清单：单一真相（id / 窗口 / 资产 / 能力目录 / 版本）
   │ cj-tauri sync（派生，勿手改）
   ├→ targets/desktop/        桌面 launcher（WebView2）    ┐ 都是外壳，只调 lingqu.build()
   └→ targets/ohos/           鸿蒙 HAP 工程（ArkWeb）      ┘ 整个 targets/ 是派生目录，已 gitignore
   │ 以 path 依赖引用
src/ + assets/                业务包：一份业务代码，两端各编各的产物
```

| 层 | 位置 | 说明 |
|---|---|---|
| 业务逻辑 | `src/main.cj` | `build(): AppSpec` + 全部 15 个 `t2h:*` 命令的注册（**每个命令名单独 `app.register`**） |
| 扫描引擎 | `src/scanner/scan.cj`（五类清单 + 评分）/ `src/scanner/baseline.cj`（C2 基线双向 diff） | 纯函数为主，可单测 |
| 依赖引擎 | `src/deps/deps.cj` | `Cargo.lock` 静态解析（**不跑子进程**）+ `[patch.*]` 提取 + 规则表 + 替代建议 + 依赖维评分 |
| 改造引擎 | `src/port/port.cj`（001–006 Cargo.toml）/ `toolchain.cj`（007–008）/ `shim.cj`（009·011–013）/ `resolve.cj`（010·014） | **14 条规则**，auto/guide 分档；`lingqu:` 标记保证幂等，apply 前逐文件备份 |
| 诊断与闸门 | `src/port/diagnose.cj`（15 条错误指纹）/ `src/port/gates.cj`（六道闸，四道可纯函数化） | 命中指纹**不调模型**，直接给"现象→根因→修法"；长尾才走 LLM |
| 引擎托管 | `src/cjh_host.cj` | cjh 生命周期（健康检查/复用/拉起/收尾/SHA256 校验） |
| 界面 | `assets/ui/index.html` | 单文件原生 HTML/CSS/JS，7 屏 + 右栏 AI dock + 设置面板 |
| 能力清单 | `assets/capabilities/default.json` | 声明命令与 WS 权限；**新增命令必须三处联动** |
| 随包引擎 | `vendor/cjh/{win-x64,linux-x64}` + `SHA256SUMS` | 免安装；`LINUX_SHA` 常量在 `src/cjh_host.cj` |
| 脚本 | `scripts/{test,run-dev,setup}.sh`（+ `.bat` 只做委托） | bash 为唯一实现，见 ADR D-012 |
| 可复用知识 | `skills/t2h-ohos-port/`（SKILL + 4 references） | 移植方法论与 12 条真机踩坑指纹，**数据飞轮的沉淀位** |

**命令全景（15 个）**：`t2h:env` `t2h:quit` `t2h:ui_report` `t2h:scan` `t2h:deps` `t2h:port` `t2h:revert`
`t2h:decisions` `t2h:diagnose` + cjh 侧 6 个（`cjh_status/start/deploy/models/settings/settings_save`）。

**新增命令三处联动**（漏一处就是运行期报错）：
① `src/main.cj` 的 `build()` 里 `app.register("t2h:xxx", XxxCommand())`
② `assets/capabilities/default.json` 的 `commands` 放行
③ `assets/ui/index.html` 里 `invoke('t2h:xxx', …)`
`cj-tauri check` 会做「声明 × 插件自述 × 实际装配」三方比对——它是门禁，不是建议。

### 4.1 装依赖（Debian/Ubuntu 口径）

```bash

export CANGJIE_STDX=<stdx>/linux_x86_64_cjnative/dynamic/stdx

# cj-tauri 的 Linux 运行时依赖（WebView 走 WebKitGTK）

  libwebkit2gtk-4.1-dev libgtk-3-dev libsoup-3.0-dev libjavascriptcoregtk-4.1-dev

# 上游框架仓（**只记远程地址，路径自己定**）
```

### 4.2 三条命令接上（顺序别变）

```bash
./scripts/setup.sh                  # 对齐 cjpm.toml 里的本机绝对路径（框架 path 依赖 + -L<native>）
export CJ_TAURI_ROOT=<你 clone 的 cj-tauri 目录>   # setup.sh 也认这个变量
./scripts/test.sh -s               # 派生骨架 + 四道闸（第一次会慢，要编 cj-tauri 骨架）

```

**判据**：`test.sh -s` 四道闸全绿（**82 例单测**）→ 窗口出现「灵渠迁移台 · Lingqu」→ 右栏状态胶囊「已连接」。
`cj-tauri` 的 Linux 上首次编译要现编框架，可能 5–15 分钟，别当成卡死。

### 4.3 Linux 上已知会碰到的点

| 现象 | 原因 / 处置 |
|---|---|
| 加载完 capability 清单后**静默退出**（无 GTK 报错） | `$DISPLAY` 是死的 X 转发会话 → 用 `xvfb-run -a -s "-screen 0 1600x900x24"` 跑，**别信 `$DISPLAY` 的存在**（§4-30） |
| 直跑产物报 `error while loading shared libraries` | 补 `LD_LIBRARY_PATH=$CJ_TAURI_ROOT/native:$CANGJIE_STDX:$CANGJIE_HOME/runtime/lib/linux_x86_64_cjnative`（§4-31） |
| `cjpm build` 报 `stdx.encoding.json ... not added as a dependency` | `CANGJIE_STDX` 没设或指错（§4-8） |
| `cjpm test` 报 `undefined symbol: cj_bridge_*` | 业务包 `cjpm.toml` 缺 `-lcjtbridge`（§4-9）；`setup.sh` 会写，换机器要重跑 |
| `ld` 报 `failed to write the output file: Permission denied` | 上一版 `main` 还开着（§4-6） |
| 链接报 `undefined symbol: _CGP7cjTauri…`（乱码符号） | 业务包公开接口变了但骨架缓存旧 → `./scripts/test.sh -c`（§4-12） |
| `cjh` 起不来 | `vendor/cjh/linux-x64/cjh` 要可执行；SHA256 校验不过会拒绝执行（`LINUX_SHA` 在 `src/cjh_host.cj`） |
| `scripts/*.sh` 报 `\r` 或 `exit 127` | 仓库有 `.gitattributes` 保证 LF；`setup.sh` 会把 Windows 形式路径 `to_posix` 归一化（§4-16） |

## 六、关键决策速查（要翻案先看 `docs/设计决策记录.md` 的原文）

| # | 决策 |
|---|---|
| D-001 | 外壳用 **cj-tauri**（不是 Electron / 官方 Tauri / 纯 Web） |
| D-002 | cjh 走**进程外 web 模式**（REST + WS `127.0.0.1:8765`），不做库内嵌 |
| D-003 | 引擎六条语义：健康检查 HTTP 200 唯一判据 / 复用优先不抢不杀 / 只收自己拉起的 / `launchHidden` / 只绑回环 / 拉起前先收自己上一只 |
| D-004 | 随包二进制必须过 **SHA256**，验不过绝不解包也不执行 |
| D-006 | 退出收尾用**守护线程**（新形态 `AppSpec` 没有 onExit 钩子） |
| D-009 | **单测只测纯函数**；进程/网络/WebView/真机以实机为准，不造假绿 |
| D-011 | **规则优先、AI 兜底**（可枚举的机械改造走规则，LLM 只处理长尾） |
| D-012 | **脚本一律 bash 为准**，`*.bat` 只做委托，不再新增 `.ps1` |
| D-013 | **静默失败零容忍**：写盘/读盘失败必须进返回值（`outError`）并由界面显示 |
| D-014 | **C2 = 人工基线双向 diff**，基线入库、基线先于扫描器、发现漏识别就补规则而不是改基线 |
| §8 纪律 | **上游回馈**：cj-tauri/cjh 能力不满足 → 提 issue（有通用修法提 PR）；**fork 先行**：tauri / openharmony-ability 不够用就**不等上游**，在 `yangyongzhen` fork 建 `fix/<工程>-<问题>` 分支先解决，patch rev 钉住继续推进（记录在 `AGENTS.md` §8，非 ADR） |
| — | 界面改动必须能被自动断言（`t2h:ui_report`），不靠肉眼看截图 |
| — | **A3 口径**：guide 项采纳 = 一次人工介入，忽略也要留痕（`t2h:decisions` → `.lingqu/port/<工程>/decisions.json`） |

**度量口径（`docs/P2-scan-口径草案.md`，已拍板，别自己改）**：
一项 = 一个**迁移单元**（命令函数 / 事件名 / 插件 / 浏览器能力 / 平台 API 符号；sites 只记账不算项）·
`C1 = D/R` 结论覆盖率 · `C2 = (基线项−漏识别)/基线项` 发现置信度 · `C3 = H/R` 人工占比 ·
处置四值域 `改造/降级/不适用/人工`，**`未知` 是禁用值**（出现即 C1<100%，门禁不放行）·
前端按**浏览器能力**计项（不按文件数）· `人工` 算有结论但要给 `question`+`candidates`，其**绝对条数**进 A3。
**C1 必须与 C3/A3 成对报**，否则"把一切都标人工"也能 100%。

## 七、验证怎么做（本项目的核心习惯，别丢）

**门禁 = 唯一交付凭证**：`./scripts/test.sh -s` 四道闸。
**界面 = 必须能被数字断言**（没有视觉也要能证明版面对）：

```bash
# 扫描/依赖/改造三屏共用一个工程路径入口：LINGQU_SCAN_PATH 会驱动 ②③④ 三屏的探针
LINGQU_SCAN_PATH=/path/to/tauri-app ./scripts/run-dev.sh
cat .lingqu/ui-report.log      # 每次一行 JSON，重点看：
#   ② 画像  scanR=24  scanC2=100  scanMissed=0  scanExtra=0
#           scanKindRows=commands:12,events:0,plugins:0,frontend:7,platform:5
#   ③ 依赖  depsTotal=625  depsPatch=0  depsUnavailable=1  depsOut=.lingqu/deps/<工程>.json
#   ④ 改造  portRules=14  portApplied=11  portAuto=10  portGuide=1  portDecided=0
#   版面    gridColumns="240px 652px 372px"  errorCount=0

# 版面 + 折叠 + 真实发问
LINGQU_UI_PROBE=1 ./scripts/run-dev.sh
# 审批卡（需临时把 cjh 置严格模式，验完恢复）
```
